- **版**: v1.1（草稿）
- **基準にした実装**: potalk.app の `index.html` **v0.15.23**（2026-10-08）。この文書と実装が食い違ったときは、**実装が正**です（この文書を直します）
- **最終更新**: 2026-11-05（§5.4 ひとことは残らない・再送しない）
- **状態**: 草稿（Draft）。外部の実装者に向けて公開し、意見をもらいながら固めていきます
- **想定するクライアント**: Web ブラウザ（`potalk.app`）、見た目を変えたデモ（`potalk.app/pop_demo/`）、CLI（`potalk-cli` など）、組み込み機器（M5Stack など）

## 1. 概要

ぽっと通話は、**運営者のサーバを通信経路に置かない** P2P 音声通話です。

- **音声**：ブラウザどうしの WebRTC（Cloudflare の TURN を中継に使う）
- **相手探し（シグナリング）**：第三者の公開 Nostr リレー（Trystero 経由）
- **部屋の一覧**：全員が入る隠し部屋（`__lobby__`）の中でのやり取り

この文書は、別の環境で作ったクライアントが**本番の potalk.app の人と同じ部屋で話せる**ようにするための約束事（ワイヤプロトコル）をまとめたものです。

### 設計の原則
1. **運営者のサーバを通信経路に置かない**：音声・シグナリング・在室のどれも、運営者が動かす機器を通しません。運営者が動かすのは、TURN の短命な資格情報を配る Cloudflare Worker だけです（中身の通信は通りません）。外部の実装も、**運営者の名前で中継サーバを立てない**でください。
2. **IP アドレスを守る（中継優先）**：ブラウザは、TURN の資格情報が取れたら `iceTransportPolicy: 'relay'` で中継だけを使います。
3. **受け取ったものは信用しない**：長さを切り詰め、型を確かめ、制御文字を取り除き、連打を間引いてから使います（§7）。
4. **知らないものは黙って無視する**：知らない action、知らない種類（`k`）、知らないフィールドを受けても、エラーにせず動き続けます（§8）。

## 2. 土台：Trystero と Nostr

### 2.1 ライブラリ
- **Trystero 0.25.4**（Nostr 戦略）。ブラウザは `https://esm.sh/trystero@0.25.4?bundle` を動的 import しています。
- ★**版を変えると黙ってつながらなくなることがあります**。Trystero は知らない設定キーを無視して既定のリレーへ落ちるので、エラーになりません。同じ 0.25 系を使ってください。
- ★Trystero を使わない環境（C++ など）では、**Trystero 自身の通信の作法**（Nostr 上でのシグナリングの形、データチャネル上での action 名と中身の包み方）も実装する必要があります。この文書はそこまでは定めていません。当面は Trystero の実装（0.25.4）を参照してください。

### 2.2 設定
| 項目 | 値 | 説明 |
| :--- | :--- | :--- |
| `appId` | `'kuramo-webrtc-call'` | 本番の空間の名前。これが違うと、ロビーも部屋も**別の世界**になります。将来、言語ごとに分ける場合は `'kuramo-webrtc-call-en'` のように接尾辞を付ける予定です |
| `relayConfig.urls` | 下の 7 本 | **キー名は `relayConfig: {urls, redundancy}`**。古い記事にある `relayUrls`／`relayRedundancy` は 0.25 では無視されます |
| `relayConfig.redundancy` | `5` | 同時に使うリレーの本数 |
| `rtcConfig` | TURN が取れたときだけ `{ iceServers, iceTransportPolicy: 'relay' }` | 取れなければ付けない（Trystero の既定の STUN で直接つなぐ） |

```javascript
const RELAYS = [
  'wss://relay.primal.net',
  'wss://purplerelay.com',
  'wss://bucket.coracle.social',
  'wss://yabu.me/v2',
  'wss://x.kojira.io',
  'wss://relay.notoshi.win',
  'wss://relay.ditto.pub'
]
```

### 2.3 TURN の資格情報
- **取得先**：`GET https://pot-turn.itsuma-kuramoto.workers.dev/` → `{ iceServers: [...] }`（Cloudflare TURN の短命な資格情報）
- **寿命**：資格情報そのものは 4 時間。ブラウザは 10 分間キャッシュし、通話中は 5 分ごとに取り直します。
- **許可の仕組み**：Worker は **Origin ヘッダーの完全一致**で許可しています（`https://potalk.app` ほか）。認証ではなく、「よそのサイトのブラウザに使わせない」ための柵です。
- ★**CLI などブラウザ以外のクライアントについて（現在の方針）**：
  - Origin を持たないので資格情報は取れません。**TURN なし（直接接続）で動かしてください**。Origin を名乗って取得するのはやめてください。
  - 直接接続でも、相手のブラウザは中継を使い続けるので、**ブラウザの人の IP は隠れたまま**です。見えるのは、**CLI を使っている人自身の IP** です（相手から見えます）。利用者に分かるように表示してください。
  - 将来、開発者ごとに **API Key** を発行し、Worker が鍵を確かめて資格情報を返す仕組みを用意する予定です。

## 3. 部屋の ID と URL

### 3.1 部屋 ID
| 種類 | 形 | 例 |
| :--- | :--- | :--- |
| 普通の部屋 | 12 バイトの乱数を base64url にした **16 文字**（`/^[A-Za-z0-9_-]{16}$/`） | `yOAQuO9gkXXMn87o` |
| 配信部屋 | `<上の 16 文字>~pk~<指紋 22 文字>` | `yOAQuO9gkXXMn87o~pk~Qx…`（§5.7） |
| 古い形式の部屋 | **部屋名そのもの**が ID（v0.12 以前のクライアント・「はじめましての部屋」） | `はじめましての部屋` |

- 常設の「ぽっと通話にようこそ」（`X7fZgwbqs8CqUF8T`）と「やまびこ部屋⛰️（5秒で返信）」（`U7PU1_IarAwtqnBf`）は、2026-10-08 から普通の部屋と同じ 16 文字の ID です。古いリンク `#room=<旧名>` は、本体が新しい ID に読み替えます（v0.15.23〜）。

- 部屋 ID は Trystero の `joinRoom(config, roomId)` の第 2 引数にそのまま渡します。
- **部屋名は ID ではありません**。同じ名前の部屋が同時に 2 つあってもかまいません。部屋名は `meta`（§5.3）とロビーで運ばれる飾りです。
- 名前の部分を切り詰めるときは **30 コードポイントまで**です。`~pk~` から後ろの指紋は**決して切らない**でください（切ると、誰にも会えない部屋になります）。

### 3.2 共有リンク
```
https://potalk.app/#room=<部屋ID>&name=<encodeURIComponent(部屋名)>
```
- 古い形 `https://potalk.app/#<部屋名>` は「入口」として扱われ、その名前でいま開いている部屋をロビーで探します。

## 4. ロビー（部屋の一覧）

### 4.1 ロビーの部屋
- Trystero の部屋 ID：`'__lobby__'`（appId は §2.2 と同じ）
- action：`'presence'` だけ

**ページを開いた人は全員ロビーに入ります**（見ているだけの人も含む）。閲覧者の数は、ロビーのピアの数で数えています。

### 4.2 在室の通知（`presence`）
**部屋に入っている人だけ**が送ります。部屋にいない人は何も送りません。

```typescript
interface Presence {
  room: string           // 部屋 ID（§3.1）
  rn: string             // 部屋名（30 コードポイントまで）
  tag?: string           // 話題タグ（30）
  tagBy?: string         // タグを付けた人の名前（20）
  bo: boolean            // 配信部屋の配信者本人か
  muted: boolean         // 自分のマイクがオフか
  elapsed: number        // この部屋に入ってからの秒数（受け手は 0〜30 日に丸める）
  talk: number           // 話している度合い 0〜3（整数）
  tt: boolean            // 配信者で、読み上げがオンか
  // ↓ 身元。「雑談部屋の人」「配信部屋の配信者」「配信部屋で話す許可を持つ人」だけが付ける。
  //   配信部屋の聞き役は付けない（名前・絵文字・成長を送らない）
  name?: string          // 表示名（20）
  emoji?: string         // 絵文字（8。無ければ受け手は '🙂'）
  stage?: string         // 成長の段階（4）
}
```

- **退出したとき**：`{ room: null }` を 1 回送ります。受け手はその人の在室をすぐ消します。
- **送る間隔**：5 秒ごと。加えて、タグの変更・ミュートの切り替え・**ロビーに新しいピアが来たとき**（部屋に入っている場合）にすぐ送ります。
- **期限切れ**：受け手は、最後に受け取ってから **30 秒**たった在室を消します。
- **一覧に出す条件**：配信部屋は、**配信者（`bo: true`）がいるときだけ**一覧に出します（聞き役だけが残った部屋に人を流さない）。

## 5. 通話の部屋

### 5.1 action の一覧
部屋に入ったら、次の 13 個の action を作ります（`room.makeAction(name)`）。

| action | 向き | 中身 | 受け手の間引き |
| :--- | :--- | :--- | :--- |
| `profile` | 全員 ⇄ 全員 | オブジェクト（§5.2） | 中身は毎回取り込む（画面の描き直しだけ 400ms で間引く） |
| `meta` | 全員 ⇄ 全員 | オブジェクト（§5.3） | 同上（500ms） |
| `chat` | 全員 → 全員 | 文字列、または入室通知のオブジェクト（§5.4） | 文字は 900ms に 1 回、入室通知は 30 秒に 1 回 |
| `react` | 全員 → 全員 | 整数 0〜7（§5.5） | 300ms に 1 回 |
| `nudge` | 相手 1 人へ | 数値 `1` | 4 秒に 1 回 |
| `bye` | 全員へ | 数値 `1` | — |
| `peers` | 全員へ（雑談部屋だけ） | `{p: [[peerId, 名前, 絵文字], …]}`（§5.6） | — |
| `tts` | 配信部屋 | オブジェクト（§5.9） | `{now}` の描き直しだけ 100ms |
| `bc` | 配信部屋 | 署名した名簿（§5.7） | 時刻が前より新しいものだけ |
| `grant` | 配信部屋 | オブジェクト（§5.8） | `resume` だけ 2 秒に 1 回 |
| `mail` | 配信部屋 | オブジェクト（§5.10） | `post` と `ask` は 1.5 秒に 1 回 |
| `oath` | 配信部屋（聞き役 ⇄ 配信者） | オブジェクト（§5.11） | `q` は相手ごとに 0.5 秒に 1 回 |
| `card` | 相手 1 人へ（求めた人 ⇄ 持ち主） | オブジェクト（§11） | `req` は 10 秒に 1 回・`q` は 0.5 秒に 1 回 |

**相手が来たとき**（`onPeerJoin`）に、その人へ `profile` と `meta` を送ります。配信部屋では、さらに次のものを送ります。
- 持っている名簿の転送（`bc`）
- おたよりの状態（`mail`）
- 読み上げの案内（`tts`）
- 募集中なら `grant {k:'reqopen'}`

### 5.2 `profile`（参加者の状態）
入ったとき、相手が来たとき、ミュートを切り替えたときに送ります。
```typescript
interface Profile {
  name: string        // 表示名（20）
  emoji: string       // 絵文字（8。既定 '🙂'）
  muted: boolean      // マイクがオフか（配信部屋の聞き役は常に true）
  stage: string       // 成長の段階（4）
  relay: boolean      // TURN の中継を使っているか（画面の ☁️ / ↔）
  since: number       // この部屋に入ってからの秒数（満室のときの順番に使う。0〜30 日）
  bgm: 'off' | 'tune' | 'amb' | 'fire'   // 自分の BGM（新しく来た人が場の BGM を初期値にもらう）
}
```
- 受け手は、届かなかったフィールドを前の値のまま残します。`relay`・`since`・`bgm` を送らない古いクライアントにも対応しています。
- ★**この action に別の種類のメッセージを載せないでください**。受け手は届いたものを全部プロフィールとして取り込みます。

### 5.3 `meta`（部屋の名前と話題タグ）
```typescript
interface Meta {
  name: string        // 部屋名（30）
  tag?: string        // 話題タグ（30）
  tagBy?: string      // 付けた人（20）
  tagAt?: number      // タグを付けた時刻（ミリ秒）
}
```
- **部屋名**：自分がまだ名前を持っていないときだけ受け取ります（先にいた人の名前が勝つ）。
- **タグ**：`tagAt` が自分の持っているものより新しければ上書きします。受け手は `tagAt` を「いま + 60 秒」までに丸めます（未来の時刻で居座られないように）。

### 5.4 `chat`（ひとこと・入室通知）
1. **ひとこと**：文字列そのもの。**60 コードポイントまで**。送る側は 1.2 秒に 1 回まで。
2. **配信部屋の入室通知**：聞き役が入ったときに 1 回送ります。
   ```json
   { "sys": "enter", "q": false, "n": "表示名" }
   ```
   - `q: true`（静かに入った）のときは `n: ""` です。受け手は「誰かが静かに入室しました」と出し、読み上げません。
   - 受け手は**配信部屋のときだけ**処理します。
- 受け手は、無視した相手のものを出しません。
3. **ひとことは、その場にいる人にだけ届き、残りません**（2026-11-05 明記）。本体は、ひとことをどこにも保存しません（端末にもサーバにも）。退出すると画面の記録も消えます。後から入った人には、入る前のひとことは見えません。利用者はこの前提で書いています。
   - **再送しないでください**：先にいた人が、後から入った人に自分の画面に残ったひとことを渡す（過去ログ共有）ことは、`chat` でも別の action でも行いません。本体の利用者が書いたひとことが、本人の知らないうちに別の人へ渡ることになるためです。互換クライアントも同じにしてください。

### 5.5 `react`（リアクション）
- 中身は次の配列の**添字**（整数 0〜7）です。**並び順は変えないでください**（相手の画面で別の絵文字になります）。
  ```javascript
  const REACTIONS = ['👏', '😂', '✨', '👍', '🤔', '😮', '🎉', '🍵']
  ```
- 送る側は 0.4 秒に 1 回まで。範囲外の値や整数でない値は捨てます。

### 5.6 `nudge`・`bye`・`peers`
- **`nudge`**：「あなたの音が届いていないので、送り直してほしい」という頼み。受けた側は、自分のマイクのストリームを一度外し、**新しい MediaStream に包み直して**送り直します（同じストリームを送り直しても相手に届かないため）。送る側は 6 秒に 1 回まで。
- **`bye`**：退出する直前に全員へ送ります。これを受け取らずに相手が消えたら、「退出」ではなく「接続が切れた」として扱います。
- **`peers`**（v0.15.22〜）：「自分は今、この人たちとつながっている」という知らせ。中身は `{p: [[peerId, 名前, 絵文字], …]}` で、自分は含めません。つながっている顔ぶれが変わったとき（相手が来た・抜けた）と、相手の名前や絵文字が分かった・変わったときに、全員へ送ります。
  - 受けた側は、知らせの中に**自分とはまだつながっていない人**がいたら、メンバー一覧に「🔄 つながり中…」として出します（3 秒続いたら。人数には数えません）。送り主が抜けたら、その人からの知らせは捨てます。
  - ロビーの在室（§4.2）でも同じことが分かりそうですが、Trystero はロビーと部屋で**同じ接続を使い回す**ので、2 人の間の接続ができないとロビーの在室も互いに届きません。そのため、つながっている人づてに知る必要があります。
  - 配信部屋では送りません（聞き役の顔ぶれを広めないため）。上限 30 件、名前 20 文字・絵文字 8 文字に切り詰めて受け取ります。知らないクライアントは無視してかまいません。

### 5.7 `bc`（配信部屋の、署名した名簿）
配信部屋で「誰の声を鳴らしてよいか」を決めるデータです。**名乗るだけでは配信者になれない**ように、配信者の鍵で署名します。

**鍵と指紋**
- 鍵：ECDSA P-256。署名のハッシュは SHA-256。
- 公開鍵の表現：**raw 形式（65 バイト）**を base64url にしたもの（約 87 文字）。
- 指紋：**公開鍵 raw の SHA-256 の先頭 16 バイト**を base64url にしたもの（22 文字）。これが部屋 ID の `~pk~` の後ろに入ります。
- 署名の表現：**IEEE P1363 形式（r‖s・64 バイト）**の base64url（約 86 文字）。WebCrypto の出力そのものです。★多くの C/C++ ライブラリが出す **DER 形式とは違う**ので、変換してください。

**中身**
```typescript
interface Roster {
  pk: string          // 配信者の公開鍵（上記）
  t: number           // 時刻（秒）。配るたびに必ず増やす
  o: string           // 配信者本人の peerId（40 文字まで）
  ids: string[]       // 話してよい人の peerId（各 40 文字まで・8 人まで）
  sig: string         // 署名（上記）
}
```
**署名する文字列**（改行区切り）：
```
部屋ID + "\n" + t + "\n" + o + "\n" + ids.join(",")
```
**受け手の検証**（すべて満たすときだけ採用）：
1. `pk` と `sig` が base64url で、`t` が安全な整数である。
2. `t` が、いままでに採用した名簿の `t` より大きい（古い名簿の使い回しを防ぐ）。
3. `pk` の指紋が、**いまいる部屋 ID の `~pk~` の後ろと一致する**（ここが要）。
4. 署名が正しい。

採用したら `o` を配信者、`ids` を話してよい人として扱います。名簿は**時間では失効しません**（配信者のタブが裏に回っても無音にならないように）。配信者は 30 秒ごとに配り直し、受け取った人は新しく来た人へそのまま転送します（署名済みなので、誰が転送してもかまいません）。

### 5.8 `grant`（話す許可・通話希望）
すべて配信部屋の中だけで使います。配信者からのもの（↓）は、**名簿の `o` から届いたものだけ**信じます。

| `k` | 向き | 中身 | 意味 |
| :--- | :--- | :--- | :--- |
| `reqopen` | 配信者 → 聞き役 | `{ on: boolean }` | 通話希望を募集しているか。★入った直後は名簿の検証が済んでおらず、配信者が誰かまだ分からないことがあります。そのとき届いたものは**捨てずに取っておき**、名簿を採用した時点で当ててください（v0.15.19）。配信者は名簿を配り直すたびに、これも送り直します |
| `raise` / `lower` | 聞き役 → 配信者 | — | 通話希望を出す／取り下げる |
| `grant` | 配信者 → 本人 | `{ tok: string }` | 話す許可を出した。`tok` は、つなぎ直したときに許可を引き継ぐための合言葉（16 バイトの base64url・10 分有効） |
| `revoke` | 配信者 → 本人 | — | 許可を取り消した |
| `resume` | 本人 → 配信者 | `{ tok: string }` | つなぎ直したので、許可を戻してほしい |
| `granted` | 配信者 → 本人 | `{ tok: string }` | 戻した |

許可そのものの正は、あくまで**署名した名簿（§5.7）**です。`grant` の通知は、画面の表示と引き継ぎのためのものです。

### 5.9 `tts`（読み上げ）
読み上げは**配信者の端末だけ**で作り、2 本目の音声として送ります。

| 中身 | 向き | 意味 |
| :--- | :--- | :--- |
| `{ sid: string, on: boolean }` | 配信者 → 各自 | 読み上げの案内。`sid` は、その相手に送る読み上げ用ストリームの id |
| `{ ok: true }` | 聞き役 → 配信者 | 「受け取れます」。**これを返した相手にだけ**読み上げのストリームを送る。音が届かないときは、もう一度送る（送り直しの合図） |
| `{ now: string \| null }` | 配信者 → 全員 | いま誰のひとことを読んでいるか（peerId）。読み終わったら `null`。無視している人の番なら、受け手は読み上げの音をその間だけ消す |

### 5.10 `mail`（おたより）
| `k` | 向き | 中身 | 意味 |
| :--- | :--- | :--- | :--- |
| `ask` | 聞き役 → 配信者 | — | 今の募集と公開中のお便りを教えて（配信者が誰か分かった時点で送る） |
| `open` | 配信者 → 全員 | `{ t: string }`（40） | お題を出して募集を始める |
| `close` | 配信者 → 全員 | — | 募集を締め切る（公開中のお便りも下げる） |
| `post` | 聞き役 → **配信者だけ** | `{ x: string }`（120） | お便りを送る。1 人 1 通（送り直すと置き換わる）。空文字は取り下げ |
| `show` | 配信者 → 全員 | `{ n: string, e: string, x: string }` | お便りを公開する（名前 20・絵文字 8・本文 120） |
| `hide` | 配信者 → 全員 | — | 公開をやめる |

送る側は 2 秒に 1 回まで。

### 5.11 `oath`（配信者の本人確認・v0.15.28）
名簿（§5.7）は署名済みなので「配信者の公開鍵」は本物ですが、**いま配信者の peerId を名乗っている接続が本当に本人か**は名簿だけでは分かりません（peerId は Nostr の合図の中の署名なしの値で、前の接続が切れたら別人が同じ ID を名乗れます）。そこで聞き役は、名簿で配信者と書かれた peerId へ乱数のチャレンジを送り、**秘密鍵の持ち主だけが返せる署名**を確かめます。

**中身**
```typescript
// 聞き役 → 配信者（名簿の o 宛て）
{ k: 'q', n: string }                 // n：乱数 16 バイトの base64url（22 文字・64 文字まで）
// 配信者 → 聞き役（送り主宛て）
{ k: 'a', n: string, sig: string }    // n：受け取った乱数そのまま／sig：下の文字列への署名（§5.7 と同じ鍵・形式）
```
**署名する文字列**（改行区切り。名簿と接頭辞で分ける）：
```
"auth" + "\n" + 部屋ID + "\n" + n
```
**受け手（聞き役）の検証**（すべて満たすときだけ採用）：
1. 送り主が、採用済みの名簿の `o`（配信者の peerId）と一致する。
2. `n` が、自分がその相手へ送った未処理のチャレンジと一致する（古い返事の使い回しを防ぐ）。
3. 署名が、**採用済みの名簿の `pk`**（部屋 ID の指紋と照合済み）で正しい。`a` に載った別の鍵は使わない。

採用したら、その peerId を**本人確認済みの配信者**として扱います。確認が済むまでは、名簿に配信者と書かれていても、**その接続の音は鳴らさず**（届いた分は取り置き、確認の瞬間に載せる）、配信者だけが出せる合図（`mail` の `open/close/show/hide`、`tts` の `{sid,on}`／`{now}`、`grant` の `reqopen/grant/revoke/granted`、BGM の源）も受け入れません。配信者の接続が切れたら確認はやり直しになります（同じ peerId を名乗る別の接続が来ても、改めて確かめます）。

聞き役は名簿を採用した時点でチャレンジを送り、返事が無ければ 2.5 秒ごとに送り直します。配信者は同じ相手からの `q` に 0.5 秒に 1 回だけ応じます。配信者自身は本人確認なしで自分を配信者として扱います。

★古いクライアント（v0.15.27 以前）の配信者は `oath` を知らないので返事をしません。その配信部屋に v0.15.28 以降の聞き役が入ると、本人確認が取れず配信者の声が鳴りません（配信者がページを読み込み直せば解消します）。

## 6. 音声（MediaStream）

- **マイクの音**：部屋に入ったら `room.addStream(マイクのストリーム)` で全員へ送ります。配信部屋の聞き役は**マイクを取りません**（ストリームを送らない）。
- **誰の音を鳴らすか**（全クライアントの義務）：
  - **雑談部屋**：無視している人以外の全員。
  - **配信部屋**：**採用した名簿（§5.7）の `o` と `ids` に載っている人だけ**。名簿に載っていない人の音は、届いても鳴らしません。この判断は受け手が自分で行うので、改造したクライアントで話しても、誰の耳にも届きません。
- **音が来たかどうか**：トラックが `live` でも、`muted` のまま中身が来ないことがあります。「届いている」は `readyState === 'live' && !muted` で判断し、来なければ `nudge`（§5.6）を送ります。
- **送り直された音の受け取り**：Trystero の `onPeerStream` は、同じストリーム id の再到着を知らせません。ブラウザ版は `RTCPeerConnection` の `track` イベントを直接受けています。

## 7. 受け取ったものの扱い

- **長さはコードポイントで数えます**（絵文字 1 つを 1 と数える）。上限は各節に書いた値です。
- **取り除く文字**：制御文字（`\p{Cc}`）、文字の向きを変える双方向制御文字、**見えない文字**（v0.16.3 から）。
  見えない文字を残すと、「jack」と「ja＋見えない文字＋ck」が画面では同じに見え、名乗りの偽装に使えます。
  ```javascript
  // 実体を貼らず、必ずエスケープで書く（見えない文字がソースに埋まると誰も気づけない）
  const UNSAFE_CHARS = /[\p{Cc}\u00AD\u034F\u061C\u115F\u1160\u180E\u200B\u200C\u200E\u200F\u2028\u2029\u202A-\u202E\u2060-\u2064\u2066-\u2069\u3164\uFEFF\uFFA0]/gu
  ```
  - 内訳：U+00AD ソフトハイフン／U+034F 結合用書記素ジョイナ／U+061C アラビア文字マーク／U+115F・U+1160・U+3164・U+FFA0 ハングルの埋め文字／U+180E モンゴル母音区切り／U+200B・U+200C 幅ゼロの空白・非結合子／U+200E・U+200F 左右マーク／U+2028・U+2029 行・段落区切り／U+202A〜U+202E 埋め込み・上書き／U+2060〜U+2064 語結合子と見えない演算子／U+2066〜U+2069 分離／U+FEFF BOM。
  - **残す文字**：U+200D（ZWJ・絵文字の結合）、U+FE00〜U+FE0F（異体字セレクタ）、U+E0020〜U+E007F（旗のタグ文字）。消すと絵文字が壊れます。
  - 送る側も同じ整形をしてから送ってください（自分の画面と相手の画面で見え方がずれないように）。
- 受け取った文字は、**HTML として解釈させない**でください（ブラウザなら `textContent` に入れる）。
- 型が違うもの（数値のはずが文字列など）は捨てるか、既定値にします。

## 8. 互換性の約束

1. **知らない action**：Trystero は、受け口のない action を黙って捨てます。新しい機能には、**新しい action 名**を使ってください。既存の action に別の種類のメッセージを混ぜてはいけません（§5.2）。
2. **知らない種類（`k`）・知らないフィールド**：既知の action の中に知らない `k` やフィールドが来たら、黙って無視します。
3. **古いクライアントが送らないフィールド**：前の値のまま残すか、既定値で補います（例：`profile` の `relay`・`since`・`bgm`）。
4. **版のやり取りはありません**：いまの実装は、相手の版を確かめていません。互換性は、上の 1〜3 だけで保っています。

| :--- | :--- | :--- |

## 10. 外部向けの在室（参考・任意）

ブラウザ版は、通話中に**公開 Nostr リレーへ直接**、在室を出しています。外部のバナーが「この部屋はいま開いているか」を、メッシュに入らずに読むためのものです。

- kind `20001`（保存されない一時イベント）、使い捨ての鍵、30 秒ごと
- d タグ：`SHA-256('potto:' + 部屋名)` の先頭 8 バイト（16 進）
- 中身：`{ e: 絵文字 }`

この仕組みは見直しを予定しています（部屋名から作るので、appId を分けても混ざる、など）。外部クライアントが送る必要はありません。

## 11. プロフィールカード（名刺交換）・`card`（v1.1・β の v0.16.1 で実装）

居合わせた相手がタップしたときだけ、相手の端末に保存してある名刺（ひとこと・アイコン画像・SNS・お礼の窓口）を P2P で受け取って表示します。運営のサーバは通りません。

### 11.1 メッセージ
```typescript
// 求める（求める人 → 持ち主 1 人）
{ k: 'req' }

// 返す（持ち主 → 求めた人だけ）
{
  k: 'res',
  bio?: string,                       // ひとこと（60 文字）
  avatar?: string,                    // アイコン画像（§11.2）
  socials?: {                         // サービスごとの ID（URL は送らない）
    x?: string,                       // /^[a-zA-Z0-9_]{1,15}$/
    github?: string,                  // /^[a-zA-Z0-9-]{1,39}$/
    note?: string,                    // /^[a-zA-Z0-9_]{3,32}$/
    instagram?: string,               // /^[a-zA-Z0-9._]{1,30}$/
    youtube?: string,                 // '@ハンドル'（/^@[\p{L}\p{N}\p{M}._\-\u00B7]{3,30}$/u・日本語可）か 'UC…'（/^UC[A-Za-z0-9_-]{22}$/）
    nostr?: string                    // /^npub1[0-9a-z]{58}$/
  },
  tip?: { p: 'ofuse' | 'amazon' | 'zap' | 'kofi' | 'bmac', id: string },   // お礼の窓口（1 つ）
  ck?: string,                        // 名刺の鍵（ECDSA P-256 の公開鍵・raw・base64url 87 文字）（§11.4）
  pr?: {                              // SNS ごとの本人確認の証拠（§11.4）。★名刺の本文への署名ではない（下の注）
    x?: string,                       // 鍵の行を含む投稿の ID（数字）
    github?: 1,                       // bio に鍵の行を書いてある、という印
    nostr?: NostrEvent                // 鍵の行に npub の鍵で署名したイベント（kind 30078）
  }
}

// 問い返し（§11.4）：確かめる人 → 持ち主
{ k: 'q', n: string }                 // 乱数 16 バイトの base64url。受け手は 64 文字まで許容
// 答え：持ち主 → 確かめる人
{ k: 'a', n: string, sig: string }    // sig は §11.4 の文への署名（P1363 の base64url）
```
- **`pr` は「証拠（proofs）」のオブジェクトです。名刺の本文への署名ではありません。**本家は名刺の本文に署名しません。本物かどうかは、問い返し（`q`/`a`・名刺の鍵の持ち主か）と、SNS 側の証拠（§11.4）で受け手が確かめます。本文は端末どうしの暗号化された接続（DTLS）で求めた人にだけ届きます。`pr` が文字列など別の形のときは、`pr` だけを捨てて名刺は表示してください（名刺ごと捨てない）。本文への署名を付けたい実装は、`pr` ではなく別の名前の欄を使ってください（知らない欄は捨てられる約束・§8）。
- **全員に配らない**：`res` は求めた相手 1 人にだけ送ります。画像を含むと数十 KB になるので、入室時に全員へ配る使い方はしないでください。
- **URL を送らない**：受け手が、種類と ID から自分で URL を組み立てます。
  | 種類 | 組み立てる URL |
  | :--- | :--- |
  | `socials.x` | `https://x.com/<id>` |
  | `socials.github` | `https://github.com/<id>` |
  | `socials.note` | `https://note.com/<id>` |
  | `socials.instagram` | `https://www.instagram.com/<id>/` |
  | `socials.youtube` | `@` で始まれば `https://www.youtube.com/@<encodeURIComponent(@ の後ろ)>`、`UC` で始まれば `https://www.youtube.com/channel/<id>`（いまは自己申告だけ・✅ の照合は未定義） |
  | `socials.nostr` | `https://njump.me/<npub>` |
  | `tip` `ofuse` | `https://ofuse.me/<id>`（`/^[a-zA-Z0-9_]{1,30}$/`。入力欄は `ofuse.me/users/<id>` の形の URL も受けて ID に切り詰める） |
  | `tip` `amazon` | `https://www.amazon.co.jp/hz/wishlist/ls/<id>`（ほしい物リストの ID `/^[a-zA-Z0-9]{10,20}$/`。短縮 URL は送らない） |
  | `tip` `zap` | lud16 のアドレス（`name@domain`）なら `lightning:<id>`、npub なら `https://njump.me/<npub>` |
  | `tip` `kofi` | `https://ko-fi.com/<id>` |
  | `tip` `bmac` | `https://buymeacoffee.com/<id>` |
- ID が上の形に合わないもの、知らない種類は、黙って捨てます（§8）。
- 外部リンクは `target="_blank" rel="noopener noreferrer nofollow"` で開きます。
- **v1.0 の草稿からの変更**：`kampa` を外しました。`instagram`・`youtube`・`amazon`・`ck`・`pr`・`q`/`a` を足しました。
- **旧形式の `verified`**：β の v0.16.0 は `verified: {x: true, …}`（「認証済み」の自己申告）を送っていました。受け手はこれを**主張としてだけ**受け取り、✅ は付けず「要確認」と示します。いまの実装は送りません。

### 11.2 アイコン画像（`avatar`）
- **送る側**：選んだ画像を正方形に切り抜き（ブラウザ版は位置と拡大を選べる）、`<canvas>` で 128×128px に縮め、JPEG で `data:` URL（Base64）にして送ります。全体を 40,000 文字に収めます（ブラウザ版は収まるまで画質を下げる）。透明な部分は白で塗ります（JPEG は透明を持てない）。**外部の URL は送りません**（表示した人の IP が画像のサーバへ漏れるため）。
  - ブラウザ版の作り方（参考・v0.16.8）：30MB を超えるファイルは断る／長辺 1024px まで縮めた状態で展開する（大きな写真を丸ごと展開しない）／半分ずつ縮めて 128px に。
- **受け取る側**（改造したクライアントは何でも送れるので、必ず確かめる）：
  - `data:image/webp;base64,`・`data:image/jpeg;base64,`・`data:image/png;base64,` で始まるものだけ受け付けます。**SVG は受け付けません。**
  - 全体で 40,000 文字までにします。
  - 一度 `<canvas>` に描き直してから表示します（受け取ったバイト列をそのまま表示に使わない）。
- **表示する場所**：タップして開いたカードの中だけです。参加者の一覧は今までどおり絵文字です。
- 無視している相手の画像は表示しません。利用者は「相手の名刺の画像を表示しない」を選べます。

### 11.3 求めてよい相手・応じる相手
- **求めてよいのは、メンバーの一覧か「ひとこと」に載っている相手だけ**です。配信部屋の、名前の出ていない聞き役には求められません。
- **無視している相手からのメッセージには応じません**（黙って捨て、返事もしない）。
- 同じ相手からの `req` には、**10 秒に 1 回**まで応じます。受け取った側は、そのセッションの間キャッシュしてかまいません。
- カードに何も登録していない人は、`{ k: 'res' }` だけを返します。
- **お礼の窓口は本人の申告です**。表示するときは「このリンクは本人が設定したものです（運営は確認していません）」と添えてください。運営はお金の流れに関わりません。

### 11.4 SNS の本人確認（受け手が確かめる）
「認証済み」を名乗るだけでは信じません。**受け手が自分の端末で**、①名刺の鍵の持ち主か、②SNS 側にその鍵の印があるか、の両方を確かめます。
- **名刺の鍵**：持ち主ごとの ECDSA P-256 の鍵（配信部屋の鍵とは別）。ブラウザ版は**取り出せない鍵**（`extractable: false`）を IndexedDB に置きます。鍵をなくしたら（ブラウザのデータを消した等）作り直し、SNS 側の証拠も出し直します（再認証）。
- **鍵の行**：`potalk1-` ＋ 指紋。指紋は `ck`（raw 公開鍵のバイト列）の SHA-256 の先頭 16 バイトを base64url にしたもの（22 文字。配信部屋の指紋と同じ作り方）。
- **SNS 側の証拠**：
  | 種類 | 証拠 | 受け手の確かめ方 |
  | :--- | :--- | :--- |
  | `x` | 鍵の行を含む投稿（`pr.x` は投稿の ID） | `https://publish.x.com/oembed?url=https://x.com/<id>/status/<pr.x>` を取得し、**応答の `author_url` のハンドルが `socials.x` と一致**し（大文字小文字は区別しない）、`html` に鍵の行が含まれる。★oEmbed は URL 中のユーザー名を無視して投稿 ID だけで引くので、URL のユーザー名で投稿者を判断してはいけない |
  | `github` | プロフィールの bio に鍵の行 | `https://api.github.com/users/<id>` の `login` が一致し、`bio` に鍵の行が含まれる |
  | `nostr` | `pr.nostr`：`kind: 30078`・タグ `['d','potalk-card']`・`content` に鍵の行を含むイベントに、`socials.nostr` の鍵で署名したもの（リレーには投稿しない） | `pubkey` が npub を復号した値と一致し、イベントの ID と署名が正しい（NIP-01） |
- **問い返し（鍵の持ち主か）**：確かめる人は `{k:'q', n}` を持ち主に送り、持ち主は次の文に名刺の鍵で署名して `{k:'a', n, sig}` を返します。
  ```
  "card" + "\n" + 部屋ID + "\n" + 問う側の peerId + "\n" + 答える側の peerId + "\n" + n
  ```
  - 確かめる人は、問う側＝自分・答える側＝問うた相手として、`ck` で検証します。**peerId を 2 つとも入れる**のは、偽者が受けた問いを本人へ横流しして答えを持ち帰る手口を防ぐためです（本人の署名には本人の peerId が入るので、偽者経由では一致しません）。
  - 署名の形式は §5.7 と同じ（ECDSA P-256 / SHA-256、IEEE P1363＝r‖s 64 バイトの base64url）。
  - 持ち主は、同じ相手の `q` に 0.5 秒に 1 回だけ応じればよい。
- **確かめるのは、受け手が求めたときだけ**です（「✅ を確かめる」を押したとき・お礼を押したとき）。開いた瞬間に X 等へ問い合わせると、受け手の IP がそのサービスに渡るためです。結果は通話のセッションの間だけ覚えます。
- **お礼の表示**：確かめて ✅ が付いた相手、または配信部屋の配信者（§5.11 で本人確認済み）のお礼窓口はふつうに出します。それ以外は控えめに出し、押したときに「本人確認されていない窓口です」と一度確認を挟みます。`zap` は、確認できた Nostr アカウントの公開プロフィール（kind 0）の `lud16` と一致するか（npub ならその npub と一致するか）まで確かめます。
- **証拠を消すと**、それ以降に確かめた人には ✅ が付きません（X の投稿・GitHub の bio は残しておく必要があります）。
