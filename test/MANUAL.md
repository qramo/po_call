# 手動テスト手順（localhost・2タブ）

git 未追跡。リファクタ中に「前と同じ挙動か」を確かめるための手順書です。
ヘッドレス（`test/smoke.py`）が見てくれるのは機械で判定できる部分だけなので、
**音が聞こえるか・見た目が崩れていないか・操作して気持ち悪くないか**はここで人が見ます。

---

## 0. 起動

```bash
cd ~/Downloads/webrtc-call
python3 test/serve.py
```

→ `http://localhost:8000/` を開く。

`python3 -m http.server` ではなくこれを使う理由は1つだけ：**appId を書き換えて本番のロビーから隔離する**ためです。
素の http.server だと、ローカルの2タブが本番と同じ `__lobby__` に入り、テスト用の部屋名が
**本番のロビー一覧に出て、公開 Nostr リレーにも publish されます**（他の利用者に新部屋の音が鳴る）。
`index.html` そのものは書き換えないので、普段どおり編集しながら使えます。

最後に一度だけ、本番と同じ条件で確認するとき：

```bash
python3 test/serve.py --prod     # appId 書き換えなし＝本番ロビーに出ます
```

### 3つの約束

| | 理由 |
|---|---|
| **必ず `localhost:8000`** | `127.0.0.1` は別オリジン扱いで TURN Worker の CORS に弾かれ、TURN が取れません（relay-first が効かず経路が変わる）。ポート 8000 も同じ理由で固定 |
| **イヤホンをする** | 2タブが同じマイクを掴み、互いのスピーカー出力を拾ってハウリングします |
| **片方はシークレットウィンドウ** | 同じブラウザだと localStorage を共有＝名前も絵文字も成長段階も同一人物になります。別人格にしないと参加者リストの確認になりません |

## 1. 基本（毎回やる・3分）

タブA＝通常ウィンドウ、タブB＝シークレットウィンドウ。両方 `http://localhost:8000/`。

- [ ] **A1** ページが開き、`これはなに？` が初回自動で出る（シークレット側）。閉じられる
- [ ] **A2** タブBは名前と絵文字が**ランダムで入っている**（例「3時のカモミール」）。編集できる
- [ ] **A3** 両タブで同じ部屋名を入れて参加 → 両方の参加者リストに**2人**が並ぶ
- [ ] **A4** タブBで喋る（or 音を鳴らす）と、**タブA側でBの絵文字が跳ねる**
- [ ] **A5** 相手の声が**聞こえる**（ヘッドレスでは絶対に分からない部分）
- [ ] **A6** 参加者リストの右端に**接続経路アイコン**が出ている（TURN が取れていれば ☁️オレンジ）
- [ ] **A6b** リストの下に**凡例**が開いて出て、**8秒ほどで畳まれ**チップ `( ☁️中継／↔直接 詳細… )` に戻る。
      チップを押すと開き、開いている間はチップが消える（1行目を押すと閉じる）
- [ ] **A6c** アイコンにマウスを乗せると、**自分の行は「あなたの…」／相手の行は「この人の…」**と出る
- [ ] **A7** タブAでミュート → タブB側でAの行が🔇＋淡色になる。解除で戻る

## 2. join / leave の対称性（リファクタの本丸・5分）

`join` が確保したものを `leave` が全部返しているか。**壊れるならほぼここ**です。
（対応表は `HANDOFF.md` の「join / leave の対応表」）

- [ ] **B1** タブAで退出 → 入力欄が開き、参加ボタンが戻り、`退出しました` と出る
- [ ] **B2** 退出直後、**タブのマイク使用中マーク（🔴）が消える**
- [ ] **B3** 退出後、タブB側の参加者リストから A が消える（10秒程度かかることがある）
- [ ] **B4** タブAで**同じ部屋に入り直す** → 普通に繋がる（`片づけが終わっていません` が出たら退行）
- [ ] **B5** 入り直したあと、**ミュートが解除された状態**から始まる
- [ ] **B6** 通話中に「つなぎ直す」を押す → 一瞬で戻り、入力欄が**チラつかない**
- [ ] **B7** ミュート中に「つなぎ直す」 → **ミュートのまま**戻る
- [ ] **B8** QRを開いた状態で退出 → QRが畳まれ、次の参加で古いリンクが残っていない

## 3. ロビー（3分）

- [ ] **C1** どちらも未参加のとき「いま通話中の部屋はありません」（探索中の表示を経てから）
- [ ] **C2** タブAだけ参加 → タブBのロビーにその部屋が出る。人数・継続時間が動く
- [ ] **C3** タブBのロビーから部屋をタップ → 確認ダイアログ → 参加できる
- [ ] **C4** 参加中に別の部屋をタップ → 「退出して移りますか？」が出て、移れる
- [ ] **C5** 全員退出 → 30秒ほどで一覧から消える（`STALE_MS`。取りこぼしより残るほうを選んでいる）
- [ ] **C6** 閲覧者数の表示が出ている（2タブなら「いま数人が見ています」）
- [ ] **C7** 🔄更新を押しても一覧が壊れない

## 4. 異常系（触ったときだけ・3分）

- [ ] **D1** 部屋名を空で参加 → `部屋名を入れてください`
- [ ] **D2** 30文字を超える部屋名 → 切り詰められ、カウンタが警告色になる
- [ ] **D3** `http://localhost:8000/#%E3%81` を開く → **ページが動く**（B-1 修正後にチェックが付く）
- [ ] **D4** Wi-Fi を切って参加 → エラーが出て、**マイクマークが消える**（B-2 修正後）
- [ ] **D5** 参加ボタンを**連打** → 二重に参加しない・エラーにならない（B-3 修正後）
- [ ] **D6** 繋がらない相手がいるときの表示が**日本語**になっている（`could not connect to peer …
      check that your TURN server URLs` のような英文が**出ないこと**）。20秒たっても誰とも
      繋がらなければ、末尾が `（相手を探しています…）` → **`（「つなぎ直す」を試してみてください）`** に変わる
      - **狙って起こしにくい**（幽霊ピア次第）ので自動テストにしていない。**出たときに見る**項目。
      - 作り方の一例：タブBで参加 → **退出せずタブごと閉じる** → すぐタブAで同じ部屋に参加。
        リレーに残ったBの announce にAが繋ぎにいって失敗することがある（毎回は再現しない）

## 4.5 配信部屋（触ったときだけ・5分）

**タブBは必ずシークレットウィンドウ。**配信者の鍵は `localStorage` にあり、**同じブラウザの
タブは全部それを共有する**ので、通常ウィンドウ同士だと**2枚目も「自分がオーナー」になります**
（＝聞き役を作れず、確認になりません）。

- [ ] **F1** 部屋名を入れて **📣 配信部屋にする** を選ぶ（既定は 🏠 雑談部屋）→ **その場で共有リンクが
      `#部屋名~pk~…` に変わる**（参加する前に配れる）
- [ ] **F2** タブAで参加 → 状態が `通話中：📣 …`／自分の行に **📣**／説明に「あなたの配信部屋です」
- [ ] **F3** そのリンクをタブB（シークレット）で開く → **部屋の種類の2択が出ていない**
      （部屋の正体はURLで決まっているため）
- [ ] **F4** タブBで参加 → **マイクの許可ダイアログが出ない**。ミュートボタンも出ない。
      自分の行は 🔇、配信者の行は 📣
- [ ] **F5** **タブAの声がタブBで聞こえる**（ヘッドレスでは分からない部分）
- [ ] **F6** タブAで相手の行の **🎙** を押す → タブBに「マイクを使う」が出る → 押すと
      **ここで初めて許可ダイアログ**が出て、タブAにBの声が届く
- [ ] **F7** タブAでもう一度 🎙 を押す → **タブBのマイク使用中マーク（🔴）が消える**／
      声が止まる／タブBは聞き役の表示に戻る
- [ ] **F8** ロビー（3つ目のタブでもよい）に **📣 付きの部屋名**が出る。タップすると
      「聞き役で入室します（マイクは使いません）」と確認が出る
- [ ] **F9** タブAで「つなぎ直す」 → **配信部屋のまま戻る**（普通の部屋に落ちない）。
      戻った直後は peerId が変わっているので、**登壇していた人には改めて 🎙 を押し直す**必要がある

## 4.7 音量（触ったときだけ・3分／**iOS 実機が本番**）

⚙️ 設定タブの一番上のスライダー。目的は相手ごとの音量差**ではなく**、
同じ端末で鳴っている他の音（YouTube・音楽）との**相対バランス**。

**鳴らし方は全端末で同じ**：`音源 → マスターGain → 出力`。`<audio>` は捨てず **muted にして残す**
（Safari はストリームを繋いだ要素が生きていないと Web Audio 側で鳴らない）。
**100% のときだけ繋ぎ替えない**＝今までと同じ鳴らし方に戻る（＝壊れたときの戻り道）。

> ★2026-08-19：最初は `audio.volume` が効くかを実行時に判定して分岐させ、**iPhone で効かなかった**。
> iOS 18.7 / Safari 26.6 は**代入がプロパティに反映される（読み返しは 0.2）のに音は変わらない**ので、
> 判定そのものが成立しない。**`.volume` に頼る実装に戻さないこと**（T35 が見張っている）。

ヘッドレスは経路が張られたことまで（T35）。**実際に音が変わるかは人しか分からない。**

- [ ] **V1** 2タブで通話 → スライダーを下げると**相手の声が小さくなり**、0% で聞こえなくなる。
      100% に戻すと**元どおり聞こえる**（ここが戻らないと永久に無音になる）
- [ ] **V2** 下げた状態で**入室音・退出音・リアクション音も一緒に小さくなる**
      （アプリの音が全部そろって下がる＝「他のアプリとのバランス」になっている）
- [ ] **V3**（★iPhone 実機・**ここがこの機能の本番**）スライダーが**実際に効く**。
      加えて **100% に戻したときにちゃんと鳴る**／**退出→再参加でも鳴る**。
      50% のまま入り直しても鳴る（`<audio>` を muted で残す癖に依存しているため）
      ← **一度ここで落ちている**（v0.8.6）。切り分けには `voltest.html`（beta のみ）が使える
- [ ] **V4** 設定はリロードしても残る（`pot-call-vol`）。**別の部屋に入っても持ち越す**
- [ ] **V5** 下げた状態で「無視」→「戻す」をしても、**戻した相手の声も同じ音量で**鳴る

## 4.8 中断からの復帰（iPhone 実機・触ったときだけ・3分）

**iOS は他アプリへ切り替えると AudioContext を `interrupted` にする**（`suspended` ではない）。
以前は戻っても誰も起こし直していなかったので、**BGM が止まったまま**／**音量<100%なら相手の声も
無音のまま**になっていた（v0.9.0 で修正）。ここはヘッドレスでは再現できない。

- [ ] **W1** 通話中に BGM を鳴らす → **他アプリへ切り替えて30秒** → 戻る → **BGM が鳴っている**
- [ ] **W2** 音量を 50% にする → 他アプリへ30秒 → 戻る → **相手の声が聞こえる**
      ← ここが無音のままなら修正が効いていない（いちばん報告されにくい壊れ方）
- [ ] **W3** 同じことを**画面ロック**でも
- [ ] **W4**（参考）**Safari 内のタブ切り替えでは中断されない**。切り分けるときは必ず**他アプリ**へ

※ 背面の**最中**に効果音や BGM が鳴らないのは**仕様**（Web Audio は中断される）。
　 直したのは「**戻ったあとに復活すること**」。混同しないこと。

## 4.9 音の出口と小窓（iPhone 実機・触ったときだけ・5分）

**このアプリが合成する音（BGM・効果音・音量を通した相手の声）は、スピーカーへ直接ではなく
`<audio id="appAudio">` から出している**（v0.10.0）。`ctx.destination` から鳴らすと
**iPhone ではほとんど聞こえない**（耳を近づけて「チリチリ」）ため。ヘッドレスは T42 が
「スピーカー直結にしていないこと」までしか見られない＝**実際に聞こえるかは人が確かめる**。

- [ ] **S1**（iPhone）BGM を鳴らす → **普通の音量で聞こえる**（「チリチリ」なら出口が壊れている）
- [ ] **S2**（iPhone）リアクション音・入退室音も同様に聞こえる
- [ ] **S3** 音を出す他のアプリ（写真・動画）に切り替える → **通話の音は止まる**（これは iOS の仕様で
      防げない）。**戻すか、相手の音が止まれば3秒ほどで鳴り直す** ← ここが復帰の確認
- [ ] **S4** 📱 小窓を押す → **部屋名と「通話中」が見える**（黒いままなら録画への差し替えが失敗）
- [ ] **S5** 小窓をタップ → **アプリに一発で戻れる**
- [ ] **S6** 小窓を出さずに他アプリ／画面ロック → **BGM が途切れない**（先読み1.5秒の確認）
- [ ] **S7** 音量を 50% にして他アプリ／ロック → **相手の声が続く**
      ← 【未決】だった「音量<100%で背面が無音」がこれで解けているかの確認

※ **PWA（ホーム画面に追加）では別物**：最前面でなくなった瞬間に OS がマイクを取り上げ、
　 小窓も出せない。**iPhone は Safari のタブで使う**のが正解（実測で確定）。

### ★push 後にしかできない確認（順序に注意）

**実機の iPhone は push してからでないと試せない。** 理由は2つあって、どちらも回避できない：

- `getUserMedia` は **https か localhost** でしか動かない。スマホから Mac を見るときの
  `http://192.168.x.x:8000` は**どちらでもない**ので、マイクが使えない。
- TURN Worker の CORS が **`https://qramo.github.io` と `http://localhost:8000` だけ**を許している。
  LAN の IP はオリジンが違うので弾かれ、TURN が取れない（＝経路も変わる）。

→ **押す前にできることは E2a で出し切ってから push する。**実機でしか分からないものだけを
push 後に回す。押した後で初めて気づくと、直すのに本番をもう一度触ることになる。

- [ ] **E4**（push 後）**iPhone / Safari** で1回繋ぐ。声が聞こえれば esm.sh・Nostr リレー・
      TURN Worker がすべて通っている（＝CSP の行き先に漏れが無い）
- [ ] **E5**（push 後）**ホーム画面に追加**してアイコンと名前が正しい
      ← `manifest-src` は比較的新しい指定で、**Safari が解釈しないと `default-src 'none'` に
      落ちて manifest がブロックされる**可能性がある。CSP を入れた回はここを必ず見ること

## ⚠️ 「push したのに直っていない」を見たら、まず**版表示**を見る

**GitHub Pages の CDN は最大10分ほど古いファイルを返す**（レスポンスの `age:` が 600 まで伸びる）。
`git push` が通っていても、実機で開いた中身が**前の版のまま**ということが普通に起きる。
2026-08-17 に実際に踏んだ：タブの折り返しを直して push → 実機で「直っていない」→
**配信されていたのは1つ前の版**だった（端末のキャッシュではなくサーバ側）。

- **判別は画面下の版表示**（`v0.8.2 β` など）。**修正のたびに版を上げておくと一発で分かる**。
- コマンドで確かめるなら、**出したはずの中身と配信中の中身を直接比べる**：

```bash
git show legacy/main:index.html | grep -o "APP_VERSION = 'v[0-9.]*'"   # 出したはず
curl -s https://qramo.github.io/po_call/ | grep -o "APP_VERSION = 'v[0-9.]*'"  # 配信中
```

**目印にする文字列は慎重に選ぶこと。**このとき `white-space:nowrap` と `max-width:440px` で
判定しようとして**両方とも前の版にも存在していた**ため、「新しい版が出ている」と誤読しかけた。
**その修正でしか出てこない名前**（今回なら `t-label`）かファイルサイズで比べる。

**★10分待っても変わらないなら、デプロイが失敗している。**キャッシュの遅れと見分けがつかないので、
**待つ前に状態を見る**こと（同じ 2026-08-17 に、8時間半止まっていたのに気づかず待っていた）：

```bash
# そのコミットのデプロイと、その結果
curl -s "https://api.github.com/repos/qramo/po_call/deployments?environment=github-pages&per_page=1" \
  | grep -oE '"(id|sha)": ?"?[^",]*'
curl -s "https://api.github.com/repos/qramo/po_call/deployments/<id>/statuses?per_page=1" \
  | grep -oE '"(state|log_url)": ?"[^"]*'
```

`state: failure` なら**やり直すまで永久に変わらない**。`log_url` の Actions 画面で
**Re-run failed jobs** を押す（`gh` があれば `gh run rerun <id> --failed`）。
**ビルド成功・デプロイだけ失敗**という形はよくあり、中身のせいではないので押し直せば通る。
`age:` が戻っているのに中身が古いままなら、CDN ではなく**配信元がまだ古い**＝この経路を疑う。

## ⚠️ SNS のカードに画像が出ないときは、ページではなく**X 側のキャッシュ**を疑う

2026-08-19：X で potalk.app を貼ると**題と説明は出るのに画像だけ出なかった**。
**旧URL（qramo.github.io）では同じ画像が出ていた**のが決め手で、原因はページではなかった。

**切り分けの順番**（ページを触る前にここまで見る）:

```bash
# ① 本番とβでタグが違うか（差が無ければページ側の問題ではない）
diff <(curl -s https://potalk.app/ | grep -iE 'og:|twitter:') \
     <(curl -s https://qramo.github.io/po_call/ | grep -iE 'og:|twitter:')
# ② 画像がクローラから取れるか（UA を名乗って確かめる）
curl -s -o /dev/null -w '%{http_code} %{content_type} %{size_download}\n' \
     -A "Twitterbot/1.0" https://potalk.app/images/ogp.png
# ③ リダイレクトが挟まっていないか
curl -s -o /dev/null -w '%{num_redirects} %{url_effective}\n' -L https://potalk.app/
```

**①〜③が正常なら、原因は X が URL 単位で覚えているカード。**打てる手は2つ:

- **切り分け**：`https://potalk.app/?x=1` のように**末尾を変えて貼る**＝別URL扱いで即座に再取得される。
  出れば「ページは正しい／古いのは X のキャッシュ」が確定する（2026-08-19 はこれで確定した）
- **素のURLを直す**：**Card Validator が効く**（`https://cards-dev.twitter.com/validator`）。
  **2026-08-19 に potalk.app で実際に直した**＝これが第一手でよい。ログインして URL を投げると
  **そのURLだけ再クロール**される。**2024年にプレビュー表示が外された**ので画面には何も出ない。
  効いたかは**ポスト作成画面に貼って**確かめること（ここを見ないと成否が分からない）。
  それでもダメなら数日〜1週間で自然に直るのを待つ

★**すでに投稿済みのポストのカードは、何をしても更新されない**（新しい投稿にだけ反映される）。
「直った」の判定は**新規に貼り直して**行うこと。

★**このとき画像ファイルの名前を変えないこと。**「取り直させる」つもりで renameすると、
**正常に出ている方（旧URL）のカードまで巻き込む**。今回は入れかけて戻した。
※ 移行（ドメイン・org の引っ越し）の最中にクローラが来ると、その時の結果が残る。
   **引っ越し直後は SNS カードを1度見ておくこと。**

## ⚠️ 「一方の窓にだけ部屋が出てこない」を見たら、まず appId を疑う

`appId` は**ページを読み込んだ瞬間に固定される**。`serve.py` を別のタグで立て直した後に
**片方の窓だけリロードし忘れる**と、2つの窓は別空間にいる＝**何回部屋を作っても永久に出会わない**。
2026-08-15 に実際に踏んだ（ヘッドレスの検証で `--tag` 違いのサーバを何度も立てていたため）。

**見分け方**：ロビー最下部が**両方の窓で「👥 いま見ているのは あなただけ です」**なら、
部屋の問題ではなく**ロビーで互いを見つけていない**。決定的な確認は、両方の窓のコンソールで：

```js
document.documentElement.outerHTML.match(/appId: '[^']+'/)[0]
```

食い違っていたら**両方をハードリロード**（⌘⇧R）すれば直る。
なお `python3 test/serve.py` は**起動しているサーバがあるとポートを奪えずに落ちる**ので、
「立て直したつもりで古いサーバが生き残っている」が普通に起きる。ターミナルの表示を見ること。

## ⚠️ 「部屋が出てこない」の切り分けは、まず `__potRelays()`

**部屋やロビーの話に入る前に、シグナリングのリレーに繋がっているかを見る。**コンソールで：

```js
window.__potRelays()   // → {open: 7, total: 7} が正常
```

- **`open: 0`** … **相手を探す経路そのものが無い**。この状態でも参加自体は成功し、画面は
  「参加中：◯◯（相手を探しています…）」のままなので、**永久に誰も来ない部屋にしか見えない**。
  - **2026-08-15 の実例**：通常プロフィールだけ `open: 0`（シークレット窓は 7/7 で互いに見えていた）。
    **リロードでは戻らず、Chrome を再起動したら直った**＝ブラウザ側が詰まっていた。
  - 直らないときは DevTools → ネットワーク → **WS** で理由を見る。
    `net::ERR_BLOCKED_BY_CLIENT` なら**拡張機能がブロックしている**（広告ブロック・プライバシー系）。
    シークレット／ゲスト窓は拡張が無効なので、切り分けにそのまま使える。
- **`open` は正常なのに相手が見えない** … そこで初めて appId（下）と幽霊ピアを疑う。
- `window.__potPc()` → `{open, made, swept}`。`made` が数百に膨らんでいたら、長く開いていた窓が
  幽霊接続で Chrome の上限に当たっている（**リロードでしか戻らない**）。

## ⚠️ 手動テストとヘッドレスは同時に走らせない

TURN の CORS の都合でどちらもポート 8000 固定なので、`smoke.py` は serve.py が動いていると起動できません。
`--no-serve` で相乗りもできますが、**そのときは appId が手動テスト側のもの（`-dev`）になります**＝
開いているタブと同じ空間で走ります。実際にこれで「つなぎ直し」が幽霊ピアに引っかかって
10秒のハンドシェイクタイムアウトを起こし、テストが不安定になりました。
**計測や切り分けをするときは手動サーバを止めて、隔離された状態で走らせること。**
